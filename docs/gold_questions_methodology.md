# Gold Questions — Structure

The evaluation gold sets live at `data/09_evaluation/<category>/gold_questions.json`.
The original student set covers four legal PDF categories: **guidance, laws,
sub_decrees, prakas**. The IRC website expansion adds source-grounded retrieval
seed questions for the website categories.

## Two tiers

The original student set has **400 gold questions**, split into two tiers by
question id.

| Category    | Total | Core (qid 1–25) | Extended (qid 26+) |
| ----------- | :---: | :-------------: | :----------------: |
| guidance    |  100  |       25        |        75          |
| laws        |   75  |       25        |        50          |
| sub_decrees |   75  |       25        |        50          |
| prakas      |  150  |       25        |       125          |
| **Total**   | **400** |   **100**     |      **300**       |

- **Core set — 100 questions.** Every question, its `expected_chunks`, and its
  `expected_answer` were written and checked individually against the source
  document. These define the target question/answer shape for the whole set.
- **Extended set — 300 questions.** Built to mirror the core set's shape, with
  each `expected_answer` taken as a verbatim passage from the corresponding
  source chunk. Quality is more uneven here: it contains weaker questions and
  some answers that do not hold up on inspection.

## Which evaluations use which tier

| Evaluation | Tier used | Why |
|---|---|---|
| Embedding comparison (`09`) | all 400 | Only `expected_chunks` matters, not answer text |
| Retrieval mode comparison (`10`) | all 400 | Same — retrieval only |
| Human gold-set validation (`11`→`12`) | all 400 | The point is to rate the set itself, both tiers |
| Answer generation (`13`) | **core 100 only** | Generated answers are compared against `expected_answer`, so the target text has to be dependable |
| LLM-as-judge scoring (`14`→`15`) | **core 100 only** | Scores the answers produced by `13` |

The cut-off is derived from the trailing number in `question_id`
(e.g. `laws_qid_026`), not from list position, so it holds even if the files are
reordered. `CORE_QID_MAX` / `CORE_SET_LIMIT` = 25 in scripts 11, 12 and 13.

## What a gold entry is

```
question_id · question · expected_chunks · context · expected_answer
```

`expected_chunks` is a single chunk id. At evaluation time the chatbot retrieves
that chunk and writes an answer, and the generated answer is compared against
`expected_answer`. That comparison only means something when `expected_answer` is
a complete, coherent passage of the retrieval chunk — the text the model would
naturally produce from it — and the question opens on the same subject as the
answer.

## Human validation

All 400 were rated by 11 evaluators (550 ratings) on clarity, relevance,
difficulty, answer quality and uniqueness. Results are in
`reports/human_golden_question_evaluation/`, reported per tier so any difference
between the core and extended sets is visible rather than assumed. The two tiers
scored 4.004 and 4.011 combined — close on the rated dimensions, which is why the
extended set is kept for the retrieval evaluations even though it is excluded
from generator comparison.

## Website Expansion Seeds

Website-category seeds are generated by
`scripts/24_prepare_website_gold_questions.py` from the active BGE-M3 metadata.
They start at `qid_026` so they are available for retrieval evaluation and human
review without being treated as the hand-checked generator-core benchmark.

Current website seed coverage:

| Category | Questions | Note |
| --- | ---: | --- |
| home | 3 | Homepage management and gross-premium blocks only |
| insurance_institutions | 10 | Institution directory chunks |
| knowledge | 10 | Gemini-extracted knowledge PDFs |
| law_regulation | 8 | Website list pages for legal document catalogs |
| news | 10 | Source-rich news article chunks |
| public_service | 10 | Public-service PDF/form chunks |
| publication | 10 | Annual report, strategic plan, glossary, and catalog chunks |
| social_programs | 10 | Source-rich social-program article chunks |
| statistics | 10 | Gemini-extracted statistics PDFs |

`announcement` and `events` are intentionally excluded from generated gold files
for now because the current indexed chunks are mostly list/navigation shells.
Re-scrape article detail bodies first, then regenerate the seed set.

The generation summary is written to `reports/website_gold_questions_seed.md`.
